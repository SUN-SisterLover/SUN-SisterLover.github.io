# 8. 隐藏面消除（节选）

## 8.1 BSP 树算法概述

建议参考文档：[(19 封私信 / 14 条消息) 几何体数据结构学习（5）BSP树 - 知乎](https://zhuanlan.zhihu.com/p/427829138)

**BSP（Binary Space Partition，二叉空间分割）在干啥**：事先用场景里多边形所在平面，把空间切成两半、两半再切……排成一棵**二叉树**。渲染时按**当前视点**在树上一走，就能得到**由远到近**的绘制顺序，配合**画家算法**（远的先画、近的后画，用覆盖表达遮挡）做隐藏面消除。

建树只做在**预处理**里；相机怎么动一般**不用重建树**，只改遍历先画哪棵子树，所以特别适合「同一场景、视点老在变」的情况。

**和画家的关系**就是先排好序再画：

```text
相对视点，把物体从后往前排好序
对每个物体
    画到屏幕上
```

---

**核心思想**。拿「包含 $T_1$ 的平面」当分割线，看视点 $e$ 和另一个三角形 $T_2$ 在平面哪一侧：

- $T_2$ 和 $e$ **在同一侧**：从 $e$ 看，$T_2$ **不可能被 $T_1$ 完全或部分挡住**，所以**先画 $T_1$、后画 $T_2$** 是安全的。
- $T_2$ 和 $e$ **各在一侧**：从 $e$ 看，$T_1$ **不可能被 $T_2$ 完全或部分挡住**，那就**先画 $T_2$、再画 $T_1$**。

对每个节点都做一次「眼睛在哪半边 → 先画远处那堆 → 再画当前分割面上那个三角 → 再画近处那堆」，整张图顺序就对上了。

---

**树长什么样**：每个结点存一个分割用的三角（及其平面），**负枝**挂代入平面方程后**全为负**的三角，**正枝**挂**全为正**的三角。渲染伪代码可以这样理解（`e` 是视点，`f_root` 是当前根平面代进点的符号）：

```text
draw(树, e):
  若树空则返回
  若 f_root(e) < 0:
      draw(正子树, e)   ← 先画离眼睛远的那一侧
      光栅化根的三角
      draw(负子树, e)   ← 再画近的这一侧
  否则:
      draw(负子树, e)
      光栅化根的三角
      draw(正子树, e)
```

两个分支只是「远子树 / 根 / 近子树」谁前谁后颠倒一下，道理就是上面**同一侧 / 两侧**那两条。

## 8.2 构造 BSP 树

**在做什么事**：把场景里一堆三角形逐个塞进树里——每个结点自带一个「分割平面」（通常就是该结点存的那个三角所在平面），新来的三角要么整坨落在负侧、要么整坨在正侧；若**横跨**平面，就先**切开**成几块「全在一侧」的小三角，再分别往下递归。

**教材式起手**（三角编号 $T_1\ldots T_N$）：

```text
树根 = 结点(T1)
对 i = 2 .. N:
    树根.add(Ti)
```

`add(T)` 相对**当前结点**的平面函数 $f$（代入顶点坐标看符号）：

- 三个顶点 **$f$ 都 $< 0$**：整三角进**负子树**（负子树空则新建一个结点再挂上去，不空就对负子树继续 `add`）。
- 三个顶点 **$f$ 都 $> 0$**：对称，进**正子树**。
- **符号不全相同**：说明三角与分割面相交，不能原样进左或右——要走**剖分**（见下）。

**跨平面时怎么切**（常见记法：$a,b$ 在一边，$c$ 在另一边）：求边与平面的交点，记为 $A$、$B$，把原三角拆成三块：

$$(a,b,A),\quad (b,B,A),\quad (A,B,c)$$

拆完以后，每一块再分别对当前结点调用 `add`（教材里会出现「两块归正枝、一块归负枝」这类写法，本质就是**按每块顶点符号**该进哪边进哪边）。**顶点绕序**要当心：新三角的绕向要和原来一致，法向才不会反。

**实现里多提一句 $\varepsilon$**：顶点到平面距离 $|f|<\varepsilon$ 时，不要当「精确在面上」去硬判，教材做法是把这些点**归到某一侧**（或把距离钳成 0），避免浮点误差下反复切出**面积几乎为 0 的细条三角**。$\varepsilon$ 是很小的正数，由你定；这和「**不要拿浮点去 == 比较**」是同一类思路——用容差代替假想的精确零。

## 8.3 Z 缓冲器

和 BSP / 画家那种「先排好全局绘制顺序」不同，**Z 缓冲（深度缓冲）**做的是：对每个像素 $(i,j)$ 单独记住「目前为止离相机**最近**的那个片段有多近」，新来的片段只有更近才把颜色写进帧缓冲。

**一帧里在干什么**：先把整张 z-buffer 清成「无穷远 / 最远」；三角形光栅化时，对每个覆盖到的像素算出插值深度 $z$（以及颜色 $c$），和当前 z-buffer 比大小：

```text
setpixel(i, j, c, z):
    若 z < z-buffer(i, j):
        z-buffer(i, j) = z
        screen(i, j) = c
```

**好处**：三角形**按什么顺序画**基本无所谓（除非两个面在同一像素上深度完全一样，再靠约定或绘制顺序打破平局）。逻辑简单，所以现代 GPU 里深度测试几乎都是**硬件 + 专用显存**在做。

### 整数 z-buffer

为省带宽/显存，深度常存成**非负整数**：把近裁剪面 $z=n$ 到远裁剪面 $z=f$ 这一段映射到 $0\ldots B-1$，$B=2^b$（$b$ 位深度）。每个整数档对应一段世界深度，档宽约 $\Delta z=(f-n)/B$。**位数越少越省、越容易把不同深度挤进同一档**——精度与内存的常规折中。

### 透视下多记一句

透视之后，缓冲里参与比较的 $z$ 和眼空间/世界空间里的距离 $z_w$ **不是线性关系**（教材会写成 $z=n+f-\dfrac{fn}{z_w}$ 一类形式）。结果是：**离相机越远，同样一个深度量化台阶对应的实际前后距离越大**，远处更容易「抢同一个深度档」，出现 **Z-fighting** 那种闪。

工程上能记三条就够：**近裁剪面别贴脸**（$n$ 不要太小）、**远平面别开太大**（$f$ 够用即可）、**别把 $n$ 设成 0** 去硬撑无穷远。硬件位数固定时，主要靠调 $n,f$ 缓解精度问题。
